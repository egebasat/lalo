# agent_bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local, customizable tool-calling agent: a Qwen3 model on CPU inside Docker, a hand-written ReAct loop, Python and MCP tools, a FastAPI NDJSON stream and a tkinter GUI on the Mac host.

**Architecture:** One job per file (spec §4). `agent.py` runs the loop against three seams: a `Backend` (raw text out), a parser (raw text → `ParsedOutput`) and a `ToolRegistry` (async tools from Python functions or MCP sessions). `server.py` wraps the loop in HTTP and streams `events.py` objects as NDJSON. The GUI is a separate host-side client.

**Tech Stack:** Python 3.12, PyTorch (CPU), transformers, FastAPI + uvicorn, pydantic v2, PyYAML, jsonschema, httpx, ddgs, trafilatura, mcp (Python SDK), tkinter + requests, pytest + pytest-asyncio + respx, Docker Desktop.

**Spec:** `plan.md` (repo root). Read it alongside this plan. Section references (§) point there.

## Global Constraints

- No agent frameworks (LangChain, smolagents, etc.). The loop is hand-written in `agent_bot/agent.py`, ≤ 200 lines, thoroughly commented.
- `agent_bot/agent.py` must not import `transformers`, `torch`, `mcp`, or `agent_bot.tools`.
- Anything model-family-specific (tags, template quirks) lives in `parsing.py` / `inference.py` only.
- The MCP module is `agent_bot/mcp_tools.py`, never `mcp.py`.
- Tool failures, timeouts and malformed calls never raise into the loop. They become visible events and are fed back to the model.
- Default model `Qwen/Qwen3-1.7B` at `/models/Qwen3-1.7B`, family `qwen3`, backend `transformers`, dtype `bfloat16`.
- Defaults: `max_new_tokens: 1024`, `temperature: 0.6`, `enable_thinking: true`, `max_iterations: 6`, `tools.timeout_s: 20`, `tools.max_result_chars: 4000`.
- The server listens on `0.0.0.0:8000` in the container and is published only as `127.0.0.1:8000`. `HF_HUB_OFFLINE=1` is set at runtime. The container memory limit is `8g`.
- The image is based on `python:3.12-slim` with CPU-only torch from `https://download.pytorch.org/whl/cpu`, includes `uv` and Node.js LTS, runs as a non-root user and builds for `linux/arm64` and `linux/amd64`.
- Secrets live only in git-ignored `.env`. `.env.example` is committed.
- The host GUI needs Python 3.10+ with tkinter and must not import anything from `agent_bot`.
- Every test except `-m slow` runs without loading a real model or touching the network.

## Review Focus

1. **Thousands separators in the calculator** ("2,340"): the model will copy the comma. Expected: a clear error telling it to drop separators, so its retry succeeds. Test in Task 5.
2. **Location strings with a country** ("Istanbul, Turkey"): Open-Meteo geocoding returns nothing for these. Expected: retry with the text before the first comma. Test in Task 5.
3. **Generation hits `max_new_tokens` inside `<think>`** (no closing tag, no answer): expected thinking shown, a parse error recorded and a visible "no answer" message instead of an empty or crashing turn. Tests in Tasks 3 and 7.
4. **Second request while a turn is running, and a client disconnecting mid-turn**: expected HTTP 409 for the overlap, and the next request after a disconnect is served (the lock is released). Test in Task 8.
5. **An MCP server whose command is missing or whose `${VAR}` is unset**: expected the app still starts, `/tools` shows that server as `failed` with the reason, and the other tools work. Test in Task 11.

### Task 5: Built-in Python tools

**Files:**
- Create: `agent_bot/tools.py`

**Interfaces:**
- Consumes: `tool`, `function_tool` and `ToolRegistry` (Task 4).

If extraction returns `None`: `ValueError("Could not extract readable text from <url>")`. The result is cut to `max_chars`.
  - `get_weather(location: str, days: int = 1) -> str`: `days` must be in 1–16. Geocode with `https://geocoding-api.open-meteo.com/v1/search?name=<loc>&count=1`. Output: the resolved place name and country, the current conditions, and one line per day with the date, a min/max in `°C`, rain % and a WMO code description.

Anything else raises `ValueError("Unsupported expression: <node type>")`. Floats are formatted with `round(x, 10)`, with the trailing `.0` dropped for integral values.

### Task 7: The agent loop and CLI (milestone 4)

**Files:**
- Create: `agent_bot/agent.py`, `agent_bot/cli.py`, `tests/fakes.py`
- Test: `tests/test_agent_loop.py`

**Interfaces:**
- Consumes: `Backend` (Task 2), `Parser` and `ParsedOutput` (Task 3), `ToolRegistry` (Task 4), events and `Tracer` (Task 6).
- Produces:
  - `@dataclass RunSettings(system_prompt: str, enable_thinking: bool, max_new_tokens: int, temperature: float, max_iterations: int, tool_timeout_s: float)`
  - `async def run(history: list[dict], *, backend, parser, registry, settings: RunSettings, tracer: Tracer = NullTracer()) -> AsyncIterator[Event]`. It mutates `history` in place by appending assistant and tool messages. The system prompt is prepended only to the messages sent to the backend and is never stored in `history`.
  - `async def stream_in_thread(it: Iterator[str]) -> AsyncIterator[str]`: drains a blocking iterator on a worker thread through an `asyncio.Queue` and `loop.call_soon_threadsafe`.
  - `tests/fakes.py`: `FakeBackend(outputs: list[str], family: str = "qwen3")`, which yields each scripted output in 3 chunks per `generate` call, records the `messages` it received and has `last_token_count = 1` per chunk. It also has `model_name == "fake"` and a `render_prompt` that returns `json.dumps(messages)`.

**Loop decisions** (the implementation must match spec §5 and §6.8):
- An iteration is one model call. Tool-call event ids are `c1`, `c2`, … per turn.
- For each call: emit `Token`s, then parse, then `tracer.record` for `prompt` (from `backend.render_prompt`), `raw_output` and `parsed`. Emit `Thinking` if present.
- The appended assistant message is `{"role": "assistant", "content": parsed.content}`, plus `"tool_calls": [{"type": "function", "function": {"name", "arguments"}}]` when there are calls. Thinking is never stored.
- No valid calls and `parse_errors` present: emit `Error("Malformed tool call: <errors joined by '; '>")` and append a `user` message: `"Your previous tool call could not be parsed (<errors>). Reply with a valid <tool_call>{\"name\": ..., \"arguments\": {...}}</tool_call> block, or answer directly."` Then continue. This counts as an iteration.
  - Exception: if the only error is `unclosed <think>`, emit `Answer("(no answer: the model ran out of tokens while thinking)")` and stop.
- No calls and no errors: emit `Answer(parsed.content or "(the model returned an empty answer)")` and stop.
- Calls are run sequentially. On the 3rd identical `(name, json.dumps(arguments, sort_keys=True))` in a turn, emit `Error("Stopped: '<name>' was called 3 times with the same arguments")` before running it, and stop.
- Each tool message is `{"role": "tool", "name": name, "content": result.content}`. `ToolCallEvent.source` is `registry.get(name).source` if the tool exists, else `"unknown"`.
- If `max_iterations` model calls are used without an answer: `Error(f"Stopped after {n} iterations without a final answer")`.
- The last event is always `Done(iterations, elapsed_s rounded to 0.1, tokens_generated)`, emitted from a `finally`-safe path. If the backend raises, emit `Error(f"Model error: {exc}")` and then `Done`.

# agent_bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local, customizable tool-calling agent:
- a Qwen3 model on the Mac's GPU via MLX;
- a hand-written ReAct loop and a FastAPI NDJSON stream, both native on the host;
- a tkinter GUI on the host;
- Python and MCP tools running in a Docker sandbox, exposed to the host as one MCP server over HTTP.

**Architecture:** One job per file (spec §4). `agent.py` runs the loop against three seams:
- a `Backend` (raw text out);
- a parser (raw text → `ParsedOutput`);
- a `ToolRegistry` (async tools).

On the host, the registry's tools come from the sandbox over MCP Streamable HTTP, refreshed every turn. In the container, `sandbox/tool_server.py` exposes its own `ToolRegistry` (Python tools plus in-container MCP servers) as that MCP server. `server.py` wraps the loop in HTTP for the GUI.

**Tech Stack:**
- Host: Python 3.12 (python.org build), mlx-lm, transformers (tokenizers, schema helper and the CPU fallback), FastAPI + uvicorn, pydantic v2, PyYAML, jsonschema, httpx, mcp (Python SDK), tkinter + requests, pytest + pytest-asyncio + respx.
- Container: python:3.12-slim with mcp, starlette/uvicorn, ddgs, trafilatura, Node.js, uv.

**Spec:** `plan.md` (repo root, **revision 2**, 2026-10-23). Read it alongside this plan. Section references (§) point there.

## Global Constraints

- No agent frameworks. The loop is hand-written in `agent_bot/agent.py`, ≤ 200 lines, thoroughly commented.
- `agent_bot/agent.py` must not import `transformers`, `torch`, `mlx`, `mlx_lm`, `mcp` or `agent_bot.tools`.
- `sandbox/tool_server.py` must not import `agent_bot.inference`, `agent_bot.agent`, `mlx`, `mlx_lm` or `torch`.
- Anything model-family-specific lives in `parsing.py` / `inference.py` only. Our code renders every prompt (`apply_chat_template`) and parses every output. No OpenAI-compatible inference server is used as a backend.
- The MCP client module is `agent_bot/mcp_tools.py`, never `mcp.py`.
- Tool failures, timeouts, malformed calls and an unreachable sandbox never raise into the loop. They become visible events and are fed back to the model.
- The host venv is `.venv`, created with `/Library/Frameworks/Python.framework/Versions/3.12/bin/python3.12` (Homebrew's 3.14 has no tkinter).
- Default model `models/Qwen3-1.7B` (host-relative), family `qwen3`, backend `mlx`. For `transformers`, the dtype default is `float32`.
- Defaults:

  | Setting | Value |

  | `temperature` | 0.6 |
  | `top_p` | 0.95 |
  | `top_k` | 20 |
  | `enable_thinking` | true |
  | `max_iterations` | 6 |
  | `tools.timeout_s` | 20 |
  | `tools.max_result_chars` | 4000 |

- **Ports:**

  - The tool server listens on `0.0.0.0:8001` in the container, published only as `127.0.0.1:8001`, path `/mcp`.
- The image has no torch and no weights. It is based on `python:3.12-slim-bookworm`, includes `uv` and Node.js LTS, runs as a non-root user and builds for `linux/arm64` and `linux/amd64`. The container memory limit is `2g`.
- Secrets live only in git-ignored `.env`. `.env.example` is committed (already written; extend it, don't replace it).
- The GUI must not import anything from `agent_bot`.
- Every test except `-m slow` runs without a real model, network or Docker.

## Review Focus

1. **Sandbox down or restarted between turns** (`docker compose restart` is how tools get added): expected an `error` event "Tool sandbox unreachable at … — is the container running?", the turn still completes, and the next turn reconnects and sees the new tool list. Tests in Task 13.
2. **Errors crossing the sandbox boundary**: a tool error inside the container must reach the model verbatim (one `"Tool 'X' failed: …"` prefix, never wrapped again as `RuntimeError`/`ToolError` on the host). The sandbox's own timeout message must win over the host's. Tests in Tasks 6 and 13.
3. **Generation hits `max_new_tokens` inside `<think>`** (no closing tag, no answer): expected thinking shown, and a visible "no answer" message instead of an empty or crashing turn. Tests in Tasks 3 (done) and 9.
4. **Second request while a turn is running, and a client disconnecting mid-turn**: expected HTTP 409 for the overlap, and the next request after a disconnect is served (the lock is released). Test in Task 10.
5. **An in-container MCP server whose command is missing or whose `${VAR}` is unset**: expected the tool server still starts, `/health` shows that server as `failed` with the reason, and the other tools work. Tests in Tasks 12 and 13.

### Task 7: MLX backend (milestone 7)

**Files:**
- Modify: `agent_bot/inference.py`, `scripts/generate.py`, `tests/test_inference.py`

**Interfaces:**
- Consumes: `ModelConfig`, `GenerationConfig` (Task 6).
- Produces:
  - `MLXBackend(cfg: ModelConfig, top_p: float = 0.95, top_k: int = 20)`, which satisfies `Backend`.
  - `create_backend(cfg: ModelConfig, gen: GenerationConfig | None = None) -> Backend`. `mlx` → `MLXBackend(cfg, gen.top_p, gen.top_k)`, `transformers` → `TransformersBackend(cfg)`, `unsloth` → the existing `NotImplementedError`.

**Threading design (spec §6.2):** MLX keeps GPU streams per thread, so the backend owns one `ThreadPoolExecutor(max_workers=1, thread_name_prefix="mlx")` for its life. `__init__` loads the model by submitting to it (and waits on the future). `generate` renders the prompt on the caller's thread, submits a producer that iterates `stream_generate` on the MLX thread and puts each non-empty `response.text` on a `queue.Queue`, then a sentinel. An exception goes on the queue instead and is re-raised in the caller. The caller only reads the queue. No `threading.Lock`: the single worker serializes generations. No custom thread classes.

**Files:**

**Interfaces:**

  - `@dataclass RunSettings(system_prompt: str, enable_thinking: bool, max_new_tokens: int, temperature: float, max_iterations: int, tool_timeout_s: float)`
  - `async def run(history: list[dict], *, backend, parser, registry, settings: RunSettings, tracer: Tracer = NullTracer()) -> AsyncIterator[Event]`. It mutates `history` in place by appending assistant and tool messages. The system prompt is prepended only to the messages sent to the backend and is never stored in `history`.

    - It yields each scripted output in 3 chunks per `generate` call and records the `messages` and `enable_thinking` it received.
    - It has `last_token_count = 3`, `model_name == "fake"` and a `render_prompt` that returns `json.dumps(messages)`.
    - An optional `block: threading.Event` makes `generate` wait until it is set (used in Task 10).
  - `tests/fakes.py`: `ListTracer` with `records: list[tuple[str, dict]]`, appending each `record(kind, data)` call.

**Loop decisions** (the implementation must match spec §5 and §6.8):
- An iteration is one model call. Tool-call event ids are `c1`, `c2`, … per turn.
- For each call:
  - emit `Token`s;
  - parse;
  - `tracer.record` for `prompt` (from `backend.render_prompt`), `raw_output` and `parsed`;
  - emit `Thinking` if present.
- The appended assistant message is `{"role": "assistant", "content": parsed.content}`, plus `"tool_calls": [{"type": "function", "function": {"name", "arguments"}}]` when there are calls. Thinking is never stored.
- No valid calls and `parse_errors` present:
  - emit `Error("Malformed tool call: <errors joined by '; '>")`;
  - append a `user` message: `"Your previous tool call could not be parsed (<errors>). Reply with a valid <tool_call>{\"name\": ..., \"arguments\": {...}}</tool_call> block, or answer directly."`;
  - continue. This counts as an iteration.
  - Exception: if the only error is `unclosed <think>`, emit `Answer("(no answer: the model ran out of tokens while thinking)")` and stop.
- No calls and no errors: emit `Answer(parsed.content or "(the model returned an empty answer)")` and stop.
- Calls run sequentially. On the 3rd identical `(name, json.dumps(arguments, sort_keys=True))` in a turn, emit `Error("Stopped: '<name>' was called 3 times with the same arguments")` before running it, and stop.
- For each call, `tracer.record("tool_call", {id, name, arguments, source})` right after the `ToolCallEvent`, and `tracer.record("tool_result", {id, content, is_error, duration_ms})` right after the `ToolResultEvent`, with the same values as the events. Calls stopped by the repeat guard never ran, so they get neither record.
- Each tool message is `{"role": "tool", "name": name, "content": result.content}`. `ToolCallEvent.source` is `registry.get(name).source` if the tool exists, else `"unknown"`.
- If `max_iterations` model calls are used without an answer: `Error(f"Stopped after {n} iterations without a final answer")`.
- The last event is always `Done(iterations, elapsed_s rounded to 0.1, tokens_generated)`. If the backend raises, emit `Error(f"Model error: {exc}")`, then `Done`.

### Task 14: Reliability eval (milestone 14)

**Files:**

**Interfaces:**
- Consumes: `create_backend`, `get_parser`, `agent.run`, `RunSettings`, `JsonlTracer`, `turn_tools` and `register_python_tools` (with `--local-tools` only).
- Produces:
  - `evals/prompts.yaml`: `runs: 3` and the 5 prompts from spec §9.1, in this shape:
    ```yaml
    - id: zen
      prompt: "Read https://peps.python.org/pep-0020/ and tell me the first line of the Zen of Python."
      required_calls:            # ordered subsequence of tool_call events
        - name: fetch_page
          args: {url: {contains: pep-0020}}
      answer_check: {contains: "beautiful is better than ugly"}
    ```
    - Arg matchers: `equals`, `contains` (case-insensitive) and `gte`. Answer `contains` is case-insensitive too.
    - Answer checks: `regex`, `contains`, `regex` + `must_appear_in_tool_results: true` (the python prompt), and `time_in_tz: Asia/Tokyo` + `tolerance_min: 2`.
    - The notes prompt has `reset_notes: true`.
  - `@dataclass RunResult(passed: bool, failed_check: str | None, infra: bool, iterations: int, elapsed_s: float, trace: str | None)`
  - `check_run(spec: dict, events: list[dict], now: datetime) -> RunResult`. A run fails on:
    - a missing or out-of-order required call (`failed_check = "call:<name>"`);
    - any `error` event (`"error"`);
    - no `answer` (`"no_answer"`);
    - a failed answer check (`"answer"`).

    It is `infra` when an `is_error` tool result from `web_search` or `fetch_page` contains any of `ConnectError`, `ConnectTimeout`, `ReadTimeout`, `HTTPStatusError`, `Ratelimit` or `DDGS`, or when the run had a "Tool sandbox unreachable" error.
  - `python -m scripts.eval [--runs N] [--only ID] [--local-tools]` (host):
    - Unless `--local-tools` is given, it first checks `http://127.0.0.1:8001/health`, and exits with "start the sandbox: docker compose up -d" if it's down.
    - For `reset_notes`, it copies `data/notes.json` to `data/notes.json.bak`, writes `[]`, runs the prompt, and restores the file in a `finally`. That works because the notes server reads the file on every call.
    - It uses a fresh history per run, wrapping each run in `turn_tools`.

  - `def _run(args: list[str], timeout_s: float = 15) -> str`: `subprocess.run(args, capture_output=True, text=True, timeout=...)`. Non-zero exit → `RuntimeError` with stderr; `-1743` in stderr → `RuntimeError("macOS blocked automation of <app>. Allow it in System Settings → Privacy & Security → Automation, then try again.")`.   - `def _open_url(url: str) -> None`: `_run(["open", url])`. Query values are built with `urllib.parse.quote`.

    - `phone`: strip spaces, dashes and parentheses, then `^\+?\d{7,15}$`; the `whatsapp://` URL gets digits only.
